# Область, подключение и хранение

Читай при начале задачи. Design Manifest владеет источниками дизайна, ресурсами и методикой сравнения. Он не владеет test runner, продуктовыми компонентами и контрактами backend.

Общая база — отдельная закреплённая поставка вне приложения. `workdir/` хранит локальные проектные настройки: repository/target IDs, выбранный стек, ссылки на файлы, приоритет mobile/desktop, источники токенов, разрешённую область дизайна и дополнительные требования. Не копируй viewport/browser из Playwright config; фиксируй фактические параметры только в evidence. Не считай каталог workdir одноразовым.

Перед реализацией уточни неизвестные решения: Figma/Penpot/предоставленный export, файл и frame/board, нужные состояния, mobile/desktop/оба, приоритет и особенности. Существующие ответы переиспользуются. Не выбирай «последний доступный frame» вместо согласованного.

Рабочие данные, exports, screenshots, JSON и HTML для UI comparison хранятся в `e2e/tmp/` выбранного worktree; добавь `/tmp/` в его e2e/.gitignore, не затрагивая прежние правила. Проверь игнорирование и отсутствие tracked данных. Для design-only задачи сначала выбери target и его локальный E2E-корень; отсутствие runner не препятствует хранению. Не складывай рабочее evidence в checkout общей базы или в общий tmp нескольких приложений.

Чтение указанного дизайна и локальная подготовка не разрешают менять дизайн или приложение. Изменение макета следует конкретной задаче и области. Комментарии, публикация библиотек, приглашения, изменение прав, MR/PR и загрузка ресурсов наружу требуют отдельного явного поручения. CI/CD не создаётся по умолчанию.

Не меняй графический стек или глобальные MCP/agent настройки ради чтения. Если нужного инструмента/доступа нет, используй предоставленный export с явным provenance либо обозначь блокировку. Не выдумывай возможности tool или API.

Перед обновлением базы сохрани выбранную адаптацию workdir. При подключённом Project Manifest используй его файловую процедуру `docs/workdir.md` и `npm run workdir -- export|restore`; она не владеет Design schema и не активирует восстановленные данные. При самостоятельной работе допустима проверенная локальная копия в новый каталог. После восстановления отдельно проверь совместимость базы, ссылки и hashes; не перезаписывай существующую адаптацию молча.
