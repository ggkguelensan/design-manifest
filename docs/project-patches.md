# Дополнения Design для проекта

Читай при добавлении проектных требований. Адаптация v2 перечисляет patches/*.json по [схеме](../schemas/project-patch.schema.json); пути не означают порядок приоритета. Каждый patch задаёт ID, точную базу, scope из source IDs, область resources/comparison/design-editing, причину и MD-ресурс с hash.

Допустим только supplement: конкретизация области, дополнительных проверок или правил обращения с ресурсами. Нельзя отменять provenance, сопоставимость, ограничения распространения и запрет автоматического изменения приложения/макета. Нельзя копировать настройки runner и предпочтения E2E. Новый тип машинной настройки сначала требует изменения схемы у её владельца.

Для самостоятельной работы без E2E сохраняй согласованные форм-факторы, порядок их рассмотрения и особенности ревью в MD-ресурсе supplement с area=comparison и scope нужных source IDs. Например: «проверять mobile и desktop; сначала mobile; отсутствие desktop evidence оставляет эту часть непроверенной». Это правило процесса, не параметры viewport и не машинная настройка runner. JSON патча владеет применимостью и состоянием согласования; не повторяй предпочтение в описаниях отдельных sources. При подключённой E2E-адаптации получай приоритет у неё по явной ссылке. Если E2E подключается позднее, согласуй одного владельца, перенеси норму к нему и замени прежнюю формулировку ссылкой после ревью; не выбирай приоритет по дате файлов.

Proposed проверяется структурно, но не применяется. Active требует review с reviewed_at и review_due_at; просроченный или будущий review отклоняется. После изменения MD обнови hash и пересмотри затронутые требования, а не только дату. Совместимость закрепляется base_revision; обновление базы требует явного ревью дополнений.

Перед активацией сопоставь требования с базой и всеми пересекающимися patches. Укажи выявленные конфликты через conflicts_with; одновременно активные конфликтующие patches с общими source IDs отклоняются независимо от порядка. Удали противоречие или оставь предложение неактивным. Валидатор не извлекает смысловые конфликты из свободного MD: отсутствие conflicts_with не доказывает совместимость. Проверка человеком/агентом обязательна.

Подробности находятся в MD-ресурсе; JSON владеет областью, статусом и временем. Не копируй полную базовую норму в ресурс. Перед расширением выполняй [SSOT-аудит](maintenance.md). Запускай validate:adaptation; его active_patches и proposed_patches разделены. Проверка структуры не разрешает публикацию или изменение дизайна.
