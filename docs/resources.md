# Источники и ресурсы дизайна

Читай для snapshot, exports и связанных assets. Источник истины — согласованный дизайн и его компоненты/токены, не screenshot другого приложения и не догадка агента.

## Snapshot

Сохрани `snapshot.json` по [схеме](../schemas/design-snapshot.schema.json). Provider, instance URL, document ID, frame/board/node, вариант, тема и состояние идентифицируют источник. Версия — реальный revision/version ID; если инструмент его не предоставляет, укажи null, время получения и ограничение. Hash export доказывает неизменность полученных bytes, но не ревизию удалённого документа.

Для локального reference укажи происхождение от пользователя и null вместо выдуманного document ID. Все выбранные references должны иметь локальный визуальный export. Отсутствующий ресурс означает неполный snapshot; не заполняй его похожей картинкой.

## Assets и инструменты

Ресурс получает уникальный ID, роль, MIME, относительный путь, SHA-256 и источник. Отдельно фиксируется допустимость распространения: allowed/restricted/unknown. Доступ к макету не означает право публиковать шрифты или приватные assets. Не сохраняй credentials, signed URLs или cookies в source refs.

Роли: reference, image, icon, font, tokens, derived. Исходники не переписываются; crop/annotation/overlay — derived с явным parent ID и описанием преобразования. Исходные PNG и полученные изображения не являются visual-regression baseline. Exported SVG не вставляется как доверенный HTML/script; для отчёта используй безопасное изображение.

Сохраняй пропорции, scale и viewport отдельно. Не растягивай reference для сокрытия расхождений. Для fonts фиксируй доступность, family/weight и использование fallback в условиях сравнения. Имена токенов/компонентов бери из источника; inferred mapping явно обозначается.

Пути и symlinks ресурсов остаются внутри выбранного review root. Не удаляй originals, на которые ссылаются comparison/report. Перед повторным использованием проверяй hashes и актуальность source; при изменении дизайна создавай новый snapshot.
