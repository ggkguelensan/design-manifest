# Adapt Design Manifest

1. Определи target и текущий worktree. При подключённом Project Manifest используй его ID/пути; при самостоятельной работе зафиксируй выбранный target явно. Проверь существующую адаптацию, инструкции и реальные возможности текущей ветки.
2. По [границам работы](../../docs/workflow.md) выясни только неизвестное: источник/точные frames или exports, состояния, форм-факторы, приоритет и особенности. Доступность инструмента не является выбором источника. Отсутствие API-доступа допускает предоставленный export с честным происхождением.
3. Закрепи ревизию базы и сохраняй долговременные решения в её игнорируемом workdir/. Не копируй реестр repositories, параметры runner или предпочтения, уже принадлежащие подключённой E2E-адаптации: ссылайся на владельца. Не записывай credentials. Рабочий аудит и evidence сохраняй только в e2e/tmp выбранного target.
4. Подключи агенту только выбранный модуль и необходимые skills нативным механизмом harness. Проверяй обнаружение и metadata отдельно от загрузки текста. Наличие файлов базы и инструкция «не читать» не доказывают изоляцию. Для нового набора возможностей используй новый сеанс; не меняй глобальную конфигурацию.
5. Подготовь короткий вход target, ссылающийся на адаптацию и закреплённую базу. Сохрани существующие инструкции; CLAUDE.md ссылается на AGENTS.md без копирования норм. Не меняй runtime приложения или макет ради подключения.
6. Проверь один разрешённый источник через [сбор ресурсов](../collect-design-resources/SKILL.md), затем по задаче [сравнение](../compare-ui-with-design/SKILL.md) и [интеграцию отчёта](../../docs/e2e-integration.md). Недоступный источник записывается как ограничение, не как успешная интеграция.
7. Сообщи выбранный target, базу, доступные возможности, расположение адаптации и выполненные проверки. Обновление базы требует проверки совместимости; не преобразуй старые пользовательские данные молча. Локальная адаптация не разрешает публикацию ресурсов.
